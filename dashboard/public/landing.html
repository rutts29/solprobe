About the project

A portfolio prototype for inspecting training-systems ideas.

SolProbe brings together a Rust telemetry sidecar, FastAPI detector service, and Next.js dashboard. It is not continuously hosted: there is no public dashboard, API, or monitoring control plane running around the clock. The project is intended for code review, local demonstrations, and technical discussion.

Built for distributed training

Designed for the failure modes that actually kill runs.

Generic monitoring tools don't know what a straggler is. SolProbe does.

DiLoCo-aware

Implements straggler, drift, and inner/outer-step rules for local and simulated telemetry; it has not been validated on a production cluster.

Fault-injection workflow

Simulation can inject thermal, memory, gradient, XID, and timeout faults to exercise the detector-to-dashboard path locally.

Diagnosis workflow

The service structures evidence and recovery suggestions, with a deterministic local fallback. External Anthropic diagnosis remains unverified.

Typed telemetry interfaces

Protobuf, REST, and WebSocket interfaces are implemented for the local prototype; compatibility guarantees are not yet offered.

Attestation design

Anchor programs and dashboard samples make the trust-layer design inspectable. There is no live on-chain integration in the app.

Operational dashboard

The Next.js dashboard renders local telemetry, policies, alerts, and sample attestation data; all backend state is in memory.

Verified local path

Start with a reproducible signal path.

Use simulation for repeatable fault injection or the Apple Silicon collector for local metrics. The Kubernetes and NVIDIA/DCGM paths are not production-ready.

# repeatable local simulation cd sidecar cargo run -- --simulate --node-id node-0 --inject-fault thermal_throttle # Apple Silicon collector (macOS only) cargo run -- --apple-gpu --node-id node-mac # NVIDIA/DCGM collection and Kubernetes deployment are prototype work.
